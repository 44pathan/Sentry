                    MAPPER VULNERABILITY SCANNER - COMPLETE HISTORY
================================================================================

1. THE BIRTH & ORIGINS OF MAPPER (July 27, 2026)
--------------------------------------------------------------------------------
* Initial Vision: Build a performant, modular web vulnerability scanner backend 
  for a hackathon presentation.
* SIEM Architecture Port: Mapper was created by porting core components from the
  existing WatchLogs SIEM project and adapting them for web security testing:
  - JWT Authentication (auth.py): Ported from WatchLogs with progressive rate-
    limiting, password hashing, and token blacklisting.
  - Rule Engine & Correlator (engine/): Adapted from WatchLogs log aggregation 
    to perform in-memory vulnerability matching and cross-tool deduplication.
  - Risk Scoring Model (risk_scorer.py): Adapted from SIEM endpoint risk formula:
      Risk Score = min(100, 20*Critical + 10*High + 3*Medium + 1*Low)
  - Storage (es_client.py): Connected to existing Elasticsearch cluster under 
    the `scan-results-YYYY.MM.DD` index prefix.


2. CORE SCANNING ENGINE & SIGNATURE IMPORTERS (Late July 2026)
--------------------------------------------------------------------------------
* 3-Layer Custom Scanner:
  1. Fetcher (fetcher.py): Async HTTP client using aiohttp, handling redirect 
     chains and TLS certificate metadata.
  2. Normalizer (normalizer.py): Converts raw HTTP responses into queryable page 
     snapshots (HTML comments, headers, meta tags, forms, inline JS).
  3. Matcher (matcher.py): Evaluates snapshots against a unified rule schema.
* Signature Importers:
  - Created wappalyzer_importer.py to extract tech stacks and version info from 
    Wappalyzer technologies.json.
  - Created nuclei_importer.py to parse Nuclei YAML templates into Mapper's 
    native rule engine format.


3. FRONTEND DASHBOARD & INFRASTRUCTURE DEPLOYMENT (Late July 2026)
--------------------------------------------------------------------------------
* Developed a modern, dark-themed UI dashboard for managing targets, viewing 
  active scans, and visualizing risk scores.
* Resolved local port conflicts and configured systemd background daemon service 
  files for automated deployment.


4. ACTIVE PROBING & ADVANCED CHECKS (Early August 2026)
--------------------------------------------------------------------------------
* Added active probing modules (active_checks.py) supporting POST-body dynamic 
  form payload injection.
* Integrated authenticated scan modes, rate-limiting, and Blind SQL Injection 
  (SQLi) payload evaluation logic.


5. CVSS SCORING REFINEMENT & ARCHITECTURE DOCS (August 10-14, 2026)
--------------------------------------------------------------------------------
* Authored end-to-end architecture flowcharts and developer guides (FLOWCHARTS.md).
* Updated CVSS enrichment logic (cvss_enricher.py), fixed match_snapshot 
  orchestration bugs, and suppressed redundant CVSS metrics on low-risk 
  findings to maintain a clean UI dashboard.


6. SERVICE STABILIZATION & HACKATHON PRESENTATION (August 18, 2026)
--------------------------------------------------------------------------------
* Fixed systemd service initialization failures caused by users.json file 
  permissions and malformed JSON scan rules.
* Resolved thread-safety race conditions, active probing runner failures, and 
  uncaught exceptions during scan execution.
* Finalized presentation deck and demo environment (HACKATHON_PRESENTATION.md).
